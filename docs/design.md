# 動画のデザイン方針

動画は「紙の作業報告書」を縦長にしたものとして組みます。目的は、AI が作った UI に見えやすい要素を避け、短時間で読める紙面にすることです。

この方針は、作業報告、会話の要約と、自由形式の既定の形式(形式の定義を書かないとき、または `base: "paper"` の同梱のスタイル)に当てはまります。自由形式では、形式の定義で色、書体、動き、紙面の組み方を変えられます([docs/format.md](format.md))。形式を作るときも、下の「避けるもの」の表を確かめることを勧めます。

## 避けるもの(いわゆる「AI っぽい UI」の兆候)

AI が生成した UI は、学習データで多数派の無難な選択(Inter 系のフォント、紫のグラデーション、控えめなアニメーションなど)に寄りやすいと説明されています([Anthropic: Improving frontend design through Skills](https://claude.com/blog/improving-frontend-design-through-skills))。具体的な兆候としてよく挙げられ、初版のデザインに当てはまっていたものは次のとおりです。

| 兆候 | 初版での該当箇所 | 出典 |
|------|------------------|------|
| 暗い背景に光彩(グロー)やぼかした円形の光 | 背景の放射グラデーション | [1][2] |
| 装飾目的の格子(グリッド)背景 | 背景の 72px 格子 | [2] |
| 紫〜インディゴ系の配色 | アクセント色 `#8ea2ff` | [1][2][3] |
| 光る状態ドット | ヘッダーの丸い点 | [1][2] |
| 見出しの上の小さなラベル・バッジ | 「AGENTIC CODING REPORT」、状態のピル型バッジ | [2] |
| 小さな番号付きの小見出し | 「01 ご依頼の内容」など | [2] |
| 同じ形のカードの羅列・大きな角丸 | 各項目のカード | [1][2] |
| カードの片側だけの色帯 | 依頼文の左の色帯 | [1][2] |
| 字間を大きく広げた英字 | 英字ラベル | [4] |

- [1] [Jeff Humble: 7 Tells that a UI is AI-Generated](https://pages.thefountaininstitute.com/posts/7-tells-that-a-ui-is-ai-generated)
- [2] [Impeccable: The visible tells of AI design](https://impeccable.style/slop)
- [3] [Why Your AI Keeps Building the Same Purple Gradient Website](https://prg.sh/ramblings/Why-Your-AI-Keeps-Building-the-Same-Purple-Gradient-Website)
- [4] [Noqta: AI design slop — overused UI patterns](https://noqta.tn/en/blog/ai-design-slop-overused-ui-patterns-fix-2026)

「AI っぽさ」は主観を含む評価で、上の兆候も一般的な傾向にすぎません。新しい要素を足すときは、この表に当てはまらないかを確認してください。

## UI UX Pro Max の使い方

`.claude/skills/ui-ux-pro-max/`(npm `ui-ux-pro-max-cli` 2.15.0、MIT)を導入しています。検索の例:

```bash
python3 .claude/skills/ui-ux-pro-max/scripts/search.py "editorial report typographic print newspaper calm professional" \
  --design-system --variance 7 --motion 3 --density 2 -p "Dopagakix"
python3 .claude/skills/ui-ux-pro-max/scripts/search.py "editorial magazine grid print typography poster" --domain style
python3 .claude/skills/ui-ux-pro-max/scripts/search.py "japanese mincho serif display" --domain google-fonts
```

注意: このスキルは AI 製品に「AI Purple(#6366F1)」系の配色を推奨するデータを持っています。「AI」「developer tool」などの語で検索すると、避けたい配色に誘導されます。

| スキルの提案 | 扱い |
|--------------|------|
| スタイル「Editorial Grid / Magazine」「Minimalism & Swiss Style」 | 採用(罫線、非対称、印刷物風の書体、余白) |
| 控えめな動き(300〜400ms、移動量 12px 前後、ease-out) | 採用 |
| コントラスト 4.5:1 以上 | 採用(全文字色で確認済み) |
| 配色(Tailwind の slate / sky) | 不採用。Tailwind の既定色そのもので、汎用的な見た目になるため |
| 書体 Libre Bodoni / Public Sans | 不採用。欧文専用のため、日本語の明朝・ゴシックで置き換え |
| ホバー・フォーカス・レスポンシブの確認項目 | 対象外(操作のない動画のため) |

## 構成の決まりごと

- 上辺に二重罫と題字「作業報告」、下辺に柱(プロジェクト名、クレジット、ページ番号)を置く。字幕のみ(`--no-voice`)の動画は、柱に「音声なし」と出す。
- 本文ページは天揃えにし、欄見出しは「罫線＋見出し」で示す。番号付きのラベルやカードは使わない。
- 項目は罫線で区切った行で並べる。検証結果は ○ / × / −、状態は ○ / △ / ! / × で表す。
- 判断を求める事項は朱色の罫と見出しで示し、題目に蛍光ペンの下線を引く。
- 最後のページは右寄せの「以上」で締める。
- 字幕は墨ベタに白抜きの帯とし、幅は一定にする。均等改行(`text-wrap: balance`)は文節の途中で切れやすいため使わない。
- 動きは「下から 14px・0.38 秒のフェードイン」と「罫線を左から引く」の 2 種類だけにする。光彩、パルス、弾むイージングは使わない。

## 図の決まりごと

図解シーン(台本の `figure`)と、変更ファイルの棒は、次のように組みます。

- 図の種類は `before_after`(変更前後の比較)と `flow`(上から下への流れ)の 2 つに限る。中身はエージェントが台本に書き、配置と描画は dopagakix が受け持つ。行数・文字数の上限は、縮小なしで本文枠に収まる量にしている。
- 枠と矢印は墨の細い罫線で描く。角丸・影・背景の塗りは使わない。変更前の枠は細く薄い罫線、変更後の枠と流れ図の段は墨の罫線にする。
- 今回変更した段は、判断事項と同じ蛍光ペンの下線(`--marker`)で示す。色は上のトークンだけを使う。
- 図には数値を書かない。数値を図にするのは、ログから集計した変更行数の棒だけにする(自己申告の数値をグラフで強調しない)。
- 変更ファイルの棒は、追加(成功の緑)と削除(失敗の赤)の行数に比例させ、表示しているファイルのうち最大のものを全幅にする。0 行なら出さない。極端に小さくても見えるよう、1% を最小の長さにする。
- 動きは既存の 2 種類に合わせる。変更前・変更後と流れ図の段は「下から 14px のフェードイン」、矢印と棒は「線を引く」動き(矢印は軸を上から、棒は左から)。変更後は 2 文目の読み上げの開始に、流れ図の段は上から順に読み上げの中ほどまでに出す。時刻は字幕の時刻から決めるので、同じ台本からは毎回同じ映像になる。

上の「避けるもの」の表との照合:

| 兆候 | 図での扱い |
|------|------------|
| 同じ形のカードの羅列・大きな角丸 | 角丸・影・塗りのない罫線の枠にし、矢印でつないで図として読ませる |
| カードの片側だけの色帯 | 使わない。変更した段は蛍光ペンの下線で示す |
| 紫〜インディゴ系の配色、光彩 | 使わない。墨と既存の成功・失敗の色だけ |
| 小さな番号付きの小見出し、見出し上のラベル | 使わない。見出しは他のシーンと同じ欄見出し。「変更前」「変更後」は枠の中の小さな見出し |

## 会話の要約の決まりごと

会話の要約の動画(`src/video/conversation.ts`)は、作業報告と同じ紙面の作法で組みます。色と書体は上のトークンだけを使い、動きも同じ 2 種類だけにします。

- 題字は「会話の要約」にする。柱の左にはチャンネル名、右には「AI による要約」とクレジットを出す。最終ページは右寄せの「以上」で締め、AI による要約であることと、数値の出どころを書く。
- 表紙は、タイトル、要旨、参加者・発言・期間の 3 つの数値、期間の日時の順に置く。数値は Bobert が数えたもの(`facts`)だけを出し、台本の文からは作らない。
- 各シーンの欄見出しは「話の流れ」「印象に残った発言」「論点」「結論」の固定の語にする。話題のシーンだけは、見出しの上に「話題」というラベルを重ねないよう、罫線の下に話題の見出しを明朝で大きく置き、説明を補助テキストの色で続ける。
- 流れは番号付きの行にする。番号は時間の順を示すだけで、数値の主張ではない。
- 引用は、明朝の大きな文字を鉤括弧で囲み、名前があれば右寄せで「― 名前」と添える。枠・片側の色帯・背景の塗りは使わない(「避けるもの」の表の、カードと色帯に当たるため)。
- 論点は、判断事項と同じ蛍光ペンの下線(`--marker`)で示し、出た意見を「―」の行で並べる。
- 結論は、決まったことを ○(成功の緑)、残ったことを △(一部完了の黄土色)で示す。小見出し「決まったこと」「残ったこと」は、変更ファイルの見出しと同じ大きさの補助テキストにする。

## 自由形式の既定の形式の決まりごと

自由形式の動画(`src/video/free.ts`)は、既定の形式では作業報告、会話の要約と同じ紙面の作法で組みます。色と書体は上のトークンだけを使い、動きも同じ 2 種類だけにします。シーンの組み方は、もとにした作業報告と会話の要約のシーンにそろえています。

- 題字と柱の右の表示は、形式の定義(`page.mast`、`page.labels`)に書いたものだけを出す。書かなければ題字は出さず、題字も日付もなければ上辺の二重罫も出さない。AI が書いたことの表示も、形式の定義に任せる(作業報告と会話の要約は自動で出す)。
- 表紙は、タイトル、要旨、数値、1 行の補足の順に置く。数値は動画ごとのファイルの `facts` にあるものだけを出し、台本の文からは作らない。最終ページは右寄せの「以上」で締め、数値の出どころを「数値: 〜」と書く。
- 見出しと説明のシーンは、会話の要約の「話題」と同じく、欄見出しを重ねずに罫線の下に見出しを明朝で大きく置く。
- 行の並び、強調する 1 文、引用は、会話の要約の「話の流れ」「論点」「印象に残った発言」と同じ組み方にする。強調する 1 文は蛍光ペンの下線(`--marker`)で示す。
- 2 つに分けた行は、会話の要約の「結論」と同じく、小見出しの下に印の付いた行を並べる。印の色は ○ が成功、△ が一部完了、× が失敗、− が未実施の色。
- 数値のシーンは、数値を 1 つずつ罫線で区切った行にし、見出しを左、数字を右に大きく置く。表紙の数値の並びを縦にしたもの。
- 画像のシーンは、画像を切り抜かずに本文の枠に収まるよう縮め(小さい画像は拡大する)、墨の細い罫線で囲む。角丸、影、背景の塗りは使わない(「避けるもの」の表の、カードに当たるため)。説明は画像の下に補助テキストの色で置く。
- 図解は作業報告の図解と同じ。流れ図の `changed` は「強調する段」の意味で使い、同じく蛍光ペンの下線で示す。
